### Gaia Pros & Cons
**pros:**
- [p] super simple iteration from your laptop *once set up*
- [p] you always know what version of operator, pi-vision, and cam-streamer are running
	- [p] and can easily change them if needed
- [p] super simple setup of new pi's (no need to image them - just point gaia at the pi and you can install everything from gaia!)

**cons:**
- [c] you all need docker desktop, probably also WSL2 for docker to work (or just switch to linux )
- [c] obfuscates the actual infra work quite heavily, so we won't really know what specific commands we're running
- [c] still an open question of how we'll have people install all this stuff themselves. most likely they can just do a docker compose file and it'll be super simple for them, but that'd need to be investigated!

*(note: i use the Obsidian theme called "Minimal" which supports the `- [p]` and `- [c]` pro/con syntax; this section may look strange on other setups!)*

### Breaking(-ish) Changes Made by Gaia Transition
- mediaMTX now runs in docker containers instead of on the pi's directly
- properly installed docker, so docker commands should work without sudo and you can just say `docker` instead of doing a really long command string
- officially sunsetting the version of pi-vision inside commander (we should rip it out imo - if you want to run pose inference on a different device, you can still use pi-vision for that i think!! so no need to duplicate code!)
- gaia sets both pi's clocks on every deploy based on your computer's time!
- unplugged both pi's from ethernet (it causes mDNS duplication - not helped by the fact that they shared ipv6 addresses due to being clones of one another!)
- after a reboot, we start the containers for pi-vision and cam streamer (+ mediaMTX) - but NOT operator. (this replicates how things worked before we moved to containers)
